# qiick registry

shadcn registry with the shared admin UI of the qiick apps, extracted from externa-core 1.4.0. Sources live in `src/` with the same `@/` paths the apps use, so `shadcn add` writes them unchanged. `npm run build` writes `../public/r/*.json`, which is committed.

## Requirements in the app

The items target apps on the Laravel React starter kit (Inertia + React 19 + Tailwind v4), like Externa and Excubia:

- `components.json` with the starter kit aliases (`@/components`, `@/components/ui`, `@/lib`, `@/hooks`) and the `@qiick` registry (see the root README).
- The `@qiick/theme` item (plus a preset such as `@qiick/theme-blue`) imported in the app CSS, plus `tw-animate-css` and the `@qiick/shadcn-utilities` item (`resources/css/shadcn-tailwind.css`, a copy of `shadcn/tailwind.css`: the `scroll-fade` and `shimmer` utilities used by `message-scroller`), imported after `tailwindcss`. The copy keeps the `shadcn` CLI package and its dev-only audit findings out of the apps. See [`docs/theme-tokens.md`](../docs/theme-tokens.md).
- The `sidebarOpen` shared Inertia prop (starter kit default), for `app-shell`.
- `react-i18next` set up, with the keys in [`locales/`](locales) merged into the app's locale files (en, it, de). Every visible or accessible string in the items goes through these keys.
- `<TooltipProvider delayDuration={0}>` around the app (starter kit `app.tsx`), for `tooltip`, `sidebar` and everything built on them.

## Changes from externa-core

The code is copied unchanged except:

- `page-header`, `data-table-toolbar`: the search `maxLength` default is `255` instead of Externa's `STRING_LIMITS.SEARCH` (same value).
- `settings-form-actions`: without Externa's unsaved-changes toolbar (Excubia's copy).
- The rows-per-page helpers of Externa's `lib/pagination.ts` are in `lib/list-per-page.ts`. `normalizePaginated` stays in each app's `lib/pagination.ts` (it needs the app's `@/types/admin`), and the name differs because `shadcn add` resolves `@/lib/pagination` to `components/ui/pagination.tsx` when both are installed together.
- `app-shell`, `app-content`, `breadcrumbs`, `app-sidebar-header`: the `AppVariant` and `BreadcrumbItem` types are declared in the files (`BreadcrumbItemType` is exported from `breadcrumbs.tsx`) instead of imported from `@/types`, because `shadcn add` rewrites `@/types` to `@/resources/js/types` in a Laravel app.
- `actions-overflow`: the test ids are `actions-overflow-*` instead of `files-action-*` (the component is not files-specific). Externa's `FilesActionsOverflow` was a typed wrapper around it and is not an item.
- `avatar`: per-user colour is `avatarToneClass(id)` on `AvatarFallback` (the same ten pastels as Externa's `lib/avatar-color.ts`, now theme tokens); the shadcn component itself is unchanged.
- `user-avatar`, `nav-user`: users are `{ id, name, email, avatar? }` (`name` is the display name) instead of Externa's `User` / `AdminUserRow`; initials come from `getInitials(name, email)`. `ConnectionDot` takes the connection `state` instead of calling `useEchoConnection()`, and uses `bg-success` / `bg-warning` instead of `bg-emerald-500` / `bg-amber-400`.
- `nav-user`: `NavUser` takes the `user` and the dropdown body as props instead of reading `usePage().props.auth`. `UserMenuContent` takes the routes (`settingsHref`, `logoutHref`, URLs or Wayfinder routes) and the language, appearance and accessibility state as props; a section is hidden when its prop is missing. Cleanup before logout (`resetChatStore()`, `router.flushAll()`) is the app's `onLogout`.
- `files-grid`: `FileGrid` is generic over the item (`items`, `renderItem`, `empty` slot, `backgroundMenu` slot) instead of taking Externa's file rows, permissions and drag-and-drop callbacks; `FileCard` takes `name`, `preview`, `cover`, `tags`, `topRight` / `bottomLeft` badges and `actions` instead of an `AdminFileRow`, and passes drag-and-drop props through. The auto-load guard on array identity, the 400px look-ahead on the scrolling panel and the Load more fallback are unchanged.
- `assistant-panel`: the drawer, ⌘J / Ctrl+J, the `ai:open` / `ai:toggle` events and the composer focus of Externa's `ai-assistant-panel.tsx`, without the chat logic (streaming, attachments, voice, presets, approvals): the app passes the thread as `children` and the composer as `composer`, and decides `enabled` (AI usable, not on the Assistant page).
- `chat-layout` is new: the list column, thread, and composer frame that `/ai` and `/chat` repeat inline, extracted with the same classes. `ChatComposer` is the frame and send behaviour of Externa's `AiComposer`, without the Externa-specific actions (attachments, voice, presets), which an app passes as `actions`.
- shadcn items added on 2026-11-06 (`item`, `kbd`, `button-group`, `command`, `scroll-area`, `chart`, `accordion`, `hover-card`, `aspect-ratio`, `carousel`, `message-scroller`, `marker`, `attachment`, `popover`) are the shadcn new-york-v4 sources as `shadcn add` writes them, unchanged.
- `avatar` is the shadcn avatar, unchanged (product decision, 2026-11-06: pure shadcn). Per-user colour moved out of the component: `avatarToneClass(id)` (`@qiick/avatar-tone`, `lib/avatar-tone.ts`) returns the theme `avatar-*` swatch classes and is passed to `AvatarFallback`'s `className` where users must be told apart (chat, presence, group members). Elsewhere the initials stay muted; `textarea` adds shadcn's `field-sizing-content` (it grows with its text); `dialog` gets shadcn's `showCloseButton` prop; `button` gets shadcn's `xs` / `icon-xs` sizes, mapped to the smallest qiick step (24px).
- `sonner`, `toast`: Externa's `lib/toast.ts` and `lib/live-announcer.ts`, with `toast.success()` moved to the message channel (top centre, no rich colour, no close button, 3 s) and the live regions renamed `app-live-polite` / `app-live-assertive`. `ui/sonner.tsx` is the shadcn component instead of Externa's older one: the app passes `theme` instead of `next-themes`, the icons carry the status colour, Sonner's rich colours are mapped to the theme's status tokens, and position, offset, duration and close button are set in the item instead of in `app.tsx`.

- shadcn primitives re-pulled from new-york-v4 on 2026-11-07 (`table`, `alert-dialog`, `input-otp`, `slider`, `switch`, `toggle-group`, `badge`, `sheet`, `tooltip`) are upstream as `shadcn add` writes them, except: `badge` keeps the qiick status variants `muted`, `success`, `warning`, `info`, `ai` and the `primary-hover` token on `default`; `sheet` keeps the translated close label (`a11y.close`); `alert-dialog` keeps the `bg-overlay` backdrop token. `table` (since 2026-11-12, upstream unchanged on that date) makes its container a scroll region with `useScrollRegion`: keyboard-focusable and named "Scrollable table" (`a11y.scrollableTable`) only while it overflows, with the scroll cue of `docs/list-page.md` and an inset focus ring. `toggle-group` items drop upstream's `min-w-0 px-3`, so the `toggle` control-size scale (square icon items, per-size padding) applies inside a group too. Every `ui/` item imports Radix from the single `radix-ui` package (`import { Dialog as DialogPrimitive } from "radix-ui"`, `Slot.Root`), as upstream does; no item depends on `@radix-ui/react-*` any more.
- `drawer` is shadcn's vaul drawer plus: `DrawerNested` (vaul `NestedRoot`), `DrawerContent` `showOverlay` (off for a drawer opened from another drawer), focus moved into the drawer on open (first `[autofocus]`, else the content, never the trigger), and the right-side width (`max-w-md`, rounded left edge).

- Wave 2 (2026-11-07), patterns from externa-core's 1.4.0 rebuild: `data-table` (`data-table.tsx`, `data-table-column-header.tsx`, `data-table-faceted-filter.tsx`), `removable-badge` and `spinner` are externa-core's files unchanged. `paginated-multi-select` is Externa's `PaginatedMultiSelect` with its own `PickerOption` type instead of `AdminSelectOption` / `Paginated` from `@/types/admin`, the field focus / open-border classes inline instead of `lib/field-control-chrome.ts`, `getInitials` from `user-avatar` instead of `lib/format.ts`, and a translated default placeholder (`picker.placeholder`) instead of `'Select…'`. `user-hover-card` is Externa's `UserHoverCard` (`components/user-hover-card.tsx`, an override there) made generic: the app passes `isOnline` instead of the card reading `useOnlineUsers()`, the user is `{ id, name, email?, avatar?, role? }` instead of `ChatUser`, the avatar is `UserAvatar` (`size="lg"`, the same 40px), and offline is the solid grey of `user-avatar` instead of 40% grey.

- `date-range-picker` (2026-11-09) is externa-core's `components/admin/date-range-picker.tsx` with: the field classes inline instead of `lib/field-control-chrome.ts`, the locale from `react-i18next` instead of `lib/format.ts`'s `appLocale()`, wire dates read and written without `date-fns` (a `YYYY-MM-DD` pattern and `Date` getters), and two additions for excubia-app's custom time range (#247): `withTime` (a start and an end time under the calendar, the range committed with Apply as `YYYY-MM-DDTHH:mm` in local time; `dateRangePicker.*` keys) and `min` / `max` (days outside are disabled). Without them it behaves as Externa's.

- `notifications` (2026-11-12) is externa-core's notification centre made app-agnostic. `notifications-drawer.tsx` renders `NotificationItem`s (`{ id, icon, title, body, link, isDocumentLink, time, isRead }`) mapped by the app instead of Externa's notification types and their hard-coded titles, folder, chat and zip links; the whole item is a link that marks it read, unread items get "Mark as read" (Externa had only "Mark as unread", which stays when the app has the endpoint), and a failed load or update says so instead of failing silently. `notifications-bell.tsx` takes a `source`, the shared `unreadCount` and an optional `subscribe` instead of reading `usePage()` and calling `ensureEcho()`, and drops the 60 s poll when realtime is off (the shared prop refreshes the badge on navigation). `lib/notifications-api.ts` is `createNotificationsSource(endpoints, toItem)` instead of fixed `/notifications` URLs and Externa's `lib/csrf.ts` / `lib/http.ts`. `lib/notification-sound.ts` has camelCase preferences (`isChatSoundEnabled`, `isNotificationSoundEnabled`) instead of the shared prop's snake_case keys, full-word names, and `playTestSound()` plays the notification chime. `sidebar-unread-badge.tsx` has the 99+ cap inline (`formatUnreadCount`) instead of `lib/format-chat-unread.ts`.

## How items install

`shadcn add` 4.23 writes every file unchanged into a Laravel React starter kit app (tested on a copy of excubia-app: all 46 files byte-identical, `tsc` green). `lib/utils.ts` and `lib/list-per-page.ts` are `registry:file` items with an explicit `resources/js/…` target: shadcn never overwrites a `registry:lib` `utils.ts` in a Laravel app, and its transforms drop a leading comment.

- `npm run lint` runs `scripts/check-ui-tokens.mjs`: no raw palette utilities, `#hex` classes or arbitrary font sizes anywhere in `src/`.
- `npm run registry:check`: `public/r` matches the sources, and every item has a playground demo.
- AI Elements on Trace (2026-11-09): shadcn rebuilt AI Elements on its new `trace` component (ui.shadcn.com/docs/ai-elements/base). `trace` is the radix-nova source (new-york-v4 has no Trace yet) with lucide's `ChevronRightIcon` instead of the icon placeholder. `reasoning`, `tool`, `chain-of-thought` and `sources` follow the shadcn base pages, as components with props instead of the old compound exports; `reasoning` opens while it streams and closes when it finishes, as upstream (#85; it stayed collapsed until then). `suggestion` and `confirmation` are new items from the same pages (`confirmation` on `Item`; Approve is brand for a write and destructive only with `isDestructive`, #83). `use-open-state.ts` is gone; `shimmer` and `code-block` stay as items but no AI Element uses them.
